# 近期变更说明

本文档用于记录 TextTreeDoc 最近一轮开发中完成的主要功能和改进，便于提交前检查、课程演示和答辩说明。

## 1. 前端展示优化

### 1.1 文档结构树双视图

文档结构树生成后，前端现在支持两种展示方式：

- `JSON 词典`：展示后端返回的原始 JSON / Python dict 结构。
- `目录树`：将 JSON 结构转换成类似命令行 tree 的可视化目录树。

目录树使用经典树形符号展示层级关系：

```text
开源许可证分析报告
├── 1. 项目背景
│   ├── 内容：开源许可证分析报告 的文档创建需要围绕主题资料进行整理...
├── 2. 相关资料分析
│   ├── 内容：系统从文本库中检索到以下相关资料...
│   └── 2.1 开源许可证概述
│       ├── 内容：开源许可证用于规定软件使用、复制、修改...
└── 5. 总结
    ├── 内容：围绕“开源许可证分析报告”...
```

该功能用于同时满足：

- 后端形成词典结构并返回 JSON。
- 前端提供更直观的文档目录树可视化。

### 1.2 下载入口和视图切换分离

之前“下载生成的 Word 文档”和“JSON / 目录树”切换控件在视觉上容易挤在一起。现在改为独立工具栏：

- 左侧：Word 下载入口或下载提示。
- 右侧：结构树显示方式切换。

这样可以避免按钮冲突，也更适合演示。

### 1.3 页面样式升级

前端整体进行了视觉优化：

- 优化顶部标题区和状态显示。
- 文本库资料卡片增加来源标签。
- 表单、按钮、结构树输出区增加更清晰的层次。
- 请求处理中禁用相关按钮，避免重复点击。
- 移动端布局更稳定。

## 2. DeepSeek 可选接入

项目增加了 DeepSeek / OpenAI-compatible API 调用能力。

当前支持通过环境变量配置：

```bash
DEEPSEEK_API_KEY=
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-v4-flash
```

前端“生成文档”区域增加了 `使用 DeepSeek` 选项。勾选后：

1. 后端优先调用大模型生成文档结构树。
2. 如果没有配置 API Key，或接口调用失败，则自动回退到本地规则生成。

同时新增了 `.env.example` 和 `.env.local`：

- `.env.example` 用于说明配置项。
- `.env.local` 用于本地保存真实 Key，已被 `.gitignore` 忽略，不应提交到 GitHub。

## 3. DeepSeek 加载动画

当用户勾选 `使用 DeepSeek` 并生成结构树时，前端会显示加载遮罩和转圈动画：

```text
DeepSeek 正在生成结构树
模型调用可能需要几秒，请稍候
```

这样可以避免大模型请求耗时期间用户误以为页面卡住。

## 4. Word 文档生成格式优化

对 `docxtpl` 模板和 `python-docx` 动态写入内容进行了格式规范化。

### 4.1 中文字体统一

生成的 Word 文档现在统一设置：

- 标题中文字体：黑体
- 正文中文字体：宋体
- 英文和数字字体：Times New Roman

### 4.2 标题颜色修复

之前 Word 内置 Heading 样式可能导致标题显示为蓝色。现在已经强制设置：

- 标题颜色：黑色
- 正文颜色：黑色
- 表格文字颜色：黑色

### 4.3 模板自动升级

`templates/report_template.docx` 仍然由程序自动生成，但现在加入了模板版本标记。旧模板不符合最新版本时，后端会自动重建模板。

## 5. 文本库和上传说明

当前文本库构建方式包括：

- 手动新增资料。
- 上传 `.txt` 文件。
- 上传 `.md` 文件。
- 上传 `.docx` 文件。
- 上传 `.pdf` 文件。

上传后，系统会解析文件文本内容，并保存到 SQLite 文本库。

PDF 上传支持文字型 PDF；扫描版 PDF 需要先进行 OCR。

资料来源标签含义：

- `seed`：系统初始化时插入的示例数据。
- `manual`：用户手动新增的资料。
- `upload`：通过文件上传解析入库的资料。

## 6. 当前项目架构说明

项目采用轻量 Web 架构：

```text
Vue 前端
  ↓ HTTP 请求
FastAPI 后端
  ↓
SQLite 文本库
  ↓
文档结构树生成模块
  ↓
docxtpl / python-docx
  ↓
生成 Word 文档
```

开发阶段前后端分离：

- 前端：Vue 3 + Vite
- 后端：FastAPI

课程演示时可以执行 `npm run build`，由 FastAPI 直接托管前端构建产物，只需要启动一个后端服务即可访问完整系统。

## 7. 提交前注意事项

提交到 GitHub 前需要确认：

- 不提交 `.env.local`。
- 不提交真实 API Key。
- 不提交 `node_modules/`。
- 不提交本地 SQLite 数据库。
- 不提交生成的 Word 文件。

这些文件已在 `.gitignore` 中配置忽略。
