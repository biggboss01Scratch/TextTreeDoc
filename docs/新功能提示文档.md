## 前端重构（前端大改动）

现在这个前端页面引导不好，用户进来不知所以然/

我想设计成流式前端架构，就是用户要一步一步地引导用户配置，最后生成文档，整个体验丝滑，不要太多冗余功能

每个页面要简洁，不要把太多东西塞在一个页面。

具体是，有一个首页（就像专业网站那样）醒目展示主要信息与引导（比如简要介绍项目、说明流程），有一个一键生成文档按钮（只不过一开始不行，因为还没配置。点了的话要提醒用户配置）。可以有那种带序号的圈，做了那一步就点亮，然后点击就可以进入相关配置。流程建议明确拆成：序号一配置文本库（没有文本库？新建！），序号二控制 Word 格式，序号三生成结构树，序号四图片编排，序号五填充正文并导出 Word。当然可以返工做前面序号的过程，只是在原来的基础上加引导，更有设计感。还有，前端页面要用平滑过渡的特效，提升体验感与高级感。

还有，注意一些常见的前端问题，比如色块、换行等。可参考之前的skills，不过这次可能不是小修是大改。
就是首页有一个序号链表示流程，是主页，还有不同配置的副页面。要突出引导与设计感。

## 当前推荐流式流程

项目应当把“结构树”和“最终正文”拆开，不再让结构树完全决定最终文档长度。

推荐流程：

1. 文本库配置：上传或录入资料，作为结构树和正文填充的知识来源。
2. Word 格式配置：单独生成或调整文档格式，包括标题编号、字体、行距、段前段后、封面、目录等。格式不直接生成正文。
3. 结构树生成：根据文本库和主题生成文档骨架，只负责章节标题、层级、章节摘要、表格/图片位置等。
4. 图片编排：在结构树生成之后，用户上传图片并插入到指定章节，形成 image block。
5. 正文填充：根据已经确认的结构树、图片位置和文本库资料生成 paragraphs 正文段落。
6. Word 导出：根据格式配置和填充后的文档树生成 docx。

结构树示例：

```json
{
  "heading": "2.5 数据库设计",
  "content": "说明数据库 ER 图和表结构",
  "children": [],
  "blocks": [
    {
      "type": "image",
      "image_id": 1,
      "caption": "图 2.5 ER 图"
    }
  ]
}
```

填充后示例：

```json
{
  "heading": "2.5 数据库设计",
  "content": "说明数据库 ER 图和表结构",
  "paragraphs": [
    "本节围绕系统数据库设计展开说明……",
    "ER 图展示了用户、课程、文档等实体之间的关系……"
  ],
  "blocks": [
    {
      "type": "image",
      "image_id": 1,
      "caption": "图 2.5 ER 图"
    }
  ]
}
```

这样结构树可以保持简洁，图片编排不会被正文生成覆盖，正文填充也可以单独重跑。


## 图片插入
对于图片插入功能实现的想法：
图片来源：用户上传图片，或者从上传的文档中提取图片（可以借助ai api用于智能化的结果）。如果是文档中提取出来的，最好可以自动提取图片名字（如果有的话）。没有的话，用户需要提供图片名。（或者默认自动命名，用户可以改）。在结构树生成完之后，会有一个图片功能页面，左侧栏显示图片缩略图和名字，右侧是一个图形化结构树。用户可以把左侧图片“拖入”右侧结构树的位置，从而自动在结构树中插入图片（可以借助ai api用于智能化的结果）
