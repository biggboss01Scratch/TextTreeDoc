# TextTreeDoc 项目需求提示文档

## 一、项目背景

这是《开源技术与应用》课程的大作业。课程候选题目中有多个方向，包括：

```
1. 当前主流大模型接口，实现参数配置与调用
2. 文本库构建
3. 文档创建
4. 根据给定 docx 文件自动提取主要结构信息
5. 用户权限管理
```

本组只需要重点完成：

```
题目 3：文档创建
```

虽然题目 1、2、4、5 和题目 3 理论上存在联系，但本项目不要把所有题目都做成一个庞大系统。项目应以题目 3 为核心，题目 2 的文本库作为题目 3 的数据来源，题目 1 的大模型接口作为可选增强，题目 4 和题目 5 作为可选扩展或轻量实现。

本项目的核心目标是：

```
查询文本库，动态构建文档结构树，形成 Python dict / JSON 结构返回；
然后基于 docxtemplate / docxtpl 模板自动生成 docx 文档；
并尽量考虑表格、图片等内容处理。
```

文本库可以自行模拟构建，不要求接入真实大型知识库。大模型 API Key 可以由用户提供，但系统必须支持没有 API Key 时也能正常运行。

```
TextTreeDoc
```

中文名：

```
基于文本库的文档结构树生成与 Word 自动生成系统
```

项目定位：

```
本项目实现一个轻量级 Web 系统，支持文本资料入库、文本检索、文档结构树生成、基于 docx 模板的 Word 文档自动生成，以及简单的权限管理。系统采用 Python + FastAPI + SQLite + docxtpl / python-docx 实现，面向课程报告、实验报告、开源项目文档等场景。
```

## 四、系统形态

请开发一个 Web 端项目，采用 B/S 架构：

```
浏览器前端
  ↓ HTTP 请求
FastAPI 后端
  ↓
SQLite 文本库
  ↓
文档结构树生成模块
  ↓
docxtpl / python-docx 文档生成模块
```

推荐技术栈：

```
后端：Python + FastAPI
数据库：SQLite
文档模板生成：docxtpl / python-docx-template
文档动态处理：python-docx
文件上传解析：python-docx，支持 txt / md / docx
前端：原生 HTML + CSS + JavaScript，或简单 Vue
接口文档：FastAPI 自动 Swagger
运行环境：Linux / Windows 均可，但代码结构要适合 Linux 部署
```

不要使用过重技术，例如 Electron、PyQt、复杂微服务、复杂向量数据库等。

## 五、核心业务流程

项目最终应能完成以下流程：

```
1. 用户打开 Web 页面
2. 用户登录系统
3. 用户向文本库添加资料
4. 系统保存资料到 SQLite
5. 用户输入一个文档主题
6. 后端查询文本库中相关资料
7. 后端动态生成文档结构树
8. 文档结构树以 Python dict / JSON 形式返回
9. 前端展示文档结构树
10. 用户点击生成 Word
11. 后端基于 docxtpl 模板和文档树生成 docx 文件
12. 用户下载生成的 docx 文档
```

# 3. 文档结构树生成

这是项目核心。

用户输入文档主题，例如：

```
开源许可证分析报告
```

后端根据主题查询文本库，找到相关文本，然后生成文档结构树。

文档结构树在后端内部使用 Python dict 表示，对前端以 JSON 返回。

示例结构：

```
{
  "title": "开源许可证分析报告",
  "sections": [
    {
      "heading": "1. 项目背景",
      "content": "介绍开源许可证的背景和意义。",
      "children": []
    },
    {
      "heading": "2. 相关概念",
      "content": "介绍 MIT、GPL、Apache 等许可证。",
      "children": [
        {
          "heading": "2.1 MIT 许可证",
          "content": "MIT 许可证是一种宽松型开源许可证。",
          "children": []
        },
        {
          "heading": "2.2 GPL 许可证",
          "content": "GPL 许可证强调代码派生作品的开源义务。",
          "children": []
        }
      ]
    },
    {
      "heading": "3. 总结",
      "content": "总结不同许可证的适用场景。",
      "children": []
    }
  ]
}
```

基础版本可以使用固定模板生成：

```
1. 项目背景
2. 相关资料分析
3. 核心内容整理
4. 应用与实现
5. 总结
```

增强版本可以调用大模型，根据文本库检索结果自动生成更自然的文档结构树。

注意：即使不接真实大模型，也必须把代码设计成未来可以接入大模型。

# 4. 基于 docxtemplate / docxtpl 自动生成 docx

课程截图明确要求：

```
基于一个 docxtemplate 模板自动生成 docx 文档
```

因此项目应优先使用：

```
docxtpl / python-docx-template
```

同时可以结合：

```
python-docx
```

推荐分工：

```
docxtpl：
用于基于模板生成固定报告框架，例如标题、作者、日期、摘要、封面等。

python-docx：
用于遍历文档结构树，动态追加多级标题、正文、表格、图片等内容。
```

生成要求：

```
1. 文档标题作为 Word 主标题
2. 一级节点作为一级标题
3. 二级节点作为二级标题
4. 三级节点作为三级标题，可选
5. 每个节点的 content 作为正文段落
6. 生成的文档保存到 generated/ 目录
7. 前端提供下载按钮
```

项目中应包含：

```
templates/report_template.docx
```

如果无法自动创建复杂模板，可以用程序在首次运行时生成一个简单模板，或者提供一个最小模板说明。

## 十、文档结构树生成策略

基础兜底方案：

```
1. 根据 topic 作为文档标题
2. 从 texts 表中查询 title、keywords、content 包含 topic 关键词的文本
3. 如果没有检索结果，使用最近的文本资料或示例文本
4. 用固定章节结构生成树：
   - 1. 项目背景
   - 2. 相关资料分析
   - 3. 核心内容整理
   - 4. 应用与实现
   - 5. 总结
5. 将检索到的文本摘要填入对应章节
6. 返回 Python dict / JSON
```

更好的检索方式：

```
将 topic 拆分关键词；
对 title / keywords / summary / content 做 LIKE 匹配；
优先使用 title、keywords 匹配结果；
结果不足时使用 summary、content 匹配；
仍不足时返回最近添加的文本作为模拟资料。
```

### 4. 不同许可证的处理原则

| ---------------------- | ------------------------------------------------------------ |

特别注意：

```
没有 LICENSE 的 GitHub 仓库，不等于可以随便复制。
```

## 补充：代码注释规范

课程截图中提到：

```

@author 项目组名称
@date 2026

```

```
app/services/text_service.py

app/services/llm_service.py
app/services/file_parser.py
app/api/text_api.py
app/api/document_api.py
app/core/database.py
```

### 2. Python 函数注释

核心函数使用接近 Doxygen 风格的 docstring：

```
def generate_tree(topic: str, related_texts: list[dict]) -> dict:
    """
    @brief 根据文档主题和相关文本生成文档结构树。

    @param topic 用户输入的文档主题。
    @param related_texts 从文本库中检索到的相关文本列表。
    @return 文档结构树，使用 Python dict 表示，可直接序列化为 JSON。

    当系统配置了大模型 API Key 时，可以调用大模型生成结构树；
    否则使用本地固定模板生成兜底结构树。
    """
```

再比如：

```
def generate_docx_from_tree(tree: dict, output_path: str) -> str:
    """
    @brief 根据文档结构树生成 docx 文件。

    @param tree 文档结构树，包含 title、sections、children 等字段。
    @param output_path 生成的 docx 文件保存路径。
    @return 生成文件的实际路径。

    该函数负责遍历文档树，将一级、二级、三级标题和正文内容写入 Word。
    对于 table 类型 block，生成 Word 表格；
    对于 image 类型 block，尝试插入图片。
    """
```

```
## texts 表
```

------

### 6. 注释数量要求

注释应遵循：

```
关键模块必须有文件说明
核心函数必须有函数说明
复杂逻辑必须有行内注释
简单代码不要过度注释
```

推荐注释重点：

```
文本库入库逻辑
文档树生成逻辑
大模型 fallback 逻辑
docxtpl / python-docx 生成 docx 逻辑
表格 / 图片处理逻辑
docx 标题结构提取逻辑
权限判断逻辑
```

不要写这种无意义注释：

```
i += 1  # i 加 1
```

要写这种解释“为什么”的注释：

```
# 没有配置大模型 API Key 时，使用固定模板保证系统在验收环境中仍可运行。
tree = fallback_tree(topic, related_texts)
```
