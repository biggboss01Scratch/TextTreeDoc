## 2. 项目背景

课程报告、实验报告、结课论文和项目设计文档通常需要经历资料整理、目录规划、格式设置、正文撰写和 Word 排版等步骤。传统方式依赖人工复制粘贴和手动排版，容易出现资料分散、结构混乱、格式不统一和重复修改成本高等问题。

TextTreeDoc 面向课程文档生成场景，尝试将“文本资料库”和“Word 文档生成”结合起来。用户可以先导入文本资料，再配置 Word 格式要求，系统根据主题生成文档结构树，支持图片插入和正文填充，最终导出 `.docx` 文档。项目支持 DeepSeek/OpenAI-compatible API 作为“智慧模式”，也保留本地规则兜底，保证没有 API Key 或网络不稳定时仍可完成演示。

## 3. 项目目标

本项目的目标包括：

- 建立一个可管理的本地文本库，用于保存课程资料、需求文档、实验材料等内容。
- 支持上传 `.txt`、`.md`、`.docx` 和文字型 `.pdf` 文件，并将内容解析入库。
- 支持通过自然语言或格式规范文档生成 Word 格式配置。
- 根据文档主题和文本库资料生成结构化目录树。
- 支持在结构树章节中插入图片素材和图注。
- 根据结构树、图片和资料填充正文。
- 使用 `python-docx` 生成可下载的 Word 文档。
- 提供完整的 README、API 文档、开发说明、贡献指南、Doxygen 注释和许可证。

## 4. 功能概述

### 4.1 文本库管理

系统支持默认文本库和自定义文本库。用户可以新增文本资料，也可以上传文件导入资料。文本资料保存到 SQLite 数据库中，后续结构树生成和正文填充都会基于选中的文本库进行。

支持文件类型：

- `.txt`
- `.md`
- `.docx`
- `.pdf`

其中 PDF 目前支持文字型 PDF，扫描版 PDF 需要先经过 OCR。

### 4.2 格式配置

格式配置页面用于生成 Word 文档格式模板。用户可以选择基础模板，例如实验报告、结课论文、技术分析报告、项目设计文档，也可以输入自然语言格式要求，例如：

```text
正文宋体小四，正文行距改为 22 磅，一级标题黑体三号，首行缩进两个中文字符。
```

系统会把格式要求解析为结构化 JSON，并在右侧以属性卡片展示。已支持的格式项包括：

- 正文字体和字号
- 标题字体和字号
- 标题编号方式
- 行距，支持倍数行距和固定磅值行距
- 首行缩进
- 正文段前段后
- 一级、二级、三级标题段前段后
- 封面、正文标题、目录、摘要、参考文献等文档组成

### 4.3 结构树生成

结构树阶段负责生成文档目录骨架。结构树不是最终正文，而是包含标题、章节层级、章节摘要、表格块和图片块的 JSON 数据。

生成流程为：

```text
用户输入主题 -> 后端检索文本库 -> 构造 Prompt 或本地规则 -> 返回结构树 JSON
```

前端默认展示图形化目录树，同时提供原始 JSON 弹窗，便于调试和说明数据结构。

### 4.4 图片编排

系统提供图片库功能，支持上传 `.png`、`.jpg`、`.jpeg` 图片。图片可以维护名称、图注和说明，并插入到结构树指定章节。

图片插入后，最终生成 Word 时会将图片和图注写入对应章节中。

### 4.5 正文填充与 Word 导出

正文填充阶段会根据结构树和文本库资料生成段落内容。填充完成后，系统调用 Word 生成模块，把标题、正文、图片、表格和格式配置合成为 `.docx` 文件。

完整流程如下：

```text
文本库 -> 格式配置 -> 结构树 -> 图片编排 -> 正文填充 -> Word 导出
```

## 5. 系统架构

TextTreeDoc 采用前后端分离架构：

- 前端：Vue 3 + Vite
- 后端：FastAPI
- 数据库：SQLite
- 文档生成：python-docx、docxtpl
- 文件解析：python-docx、pypdf
- AI 接入：DeepSeek/OpenAI-compatible API

架构示意：

```text
浏览器
  |
  v
Vue 3 前端
  |
  v
FastAPI 后端
  |
  +--> SQLite 数据库
  +--> uploaded/ 上传文件
  +--> generated/ 生成文档
  +--> templates/ Word 模板
  +--> DeepSeek/OpenAI-compatible API
```

## 8. 前端设计

前端使用 Vue 3 单页应用形式组织。页面不是传统菜单式工具，而是按照真实文档生成流程拆分为多个步骤：

1. 首页：展示流程概览。
2. 文本库：选择文本库、导入资料。
3. 格式：配置 Word 格式模板。
4. 结构树：生成并查看目录骨架。
5. 图片：上传图片并插入章节。
6. 填充导出：填充正文并下载 Word。

前端设计重点：

- 用流程式导航降低用户理解成本。
- 用图形化目录树替代大段 JSON 直接展示。
- 将 JSON 作为弹窗调试信息，而不是默认暴露给普通用户。
- 使用顶部提示弹窗显示成功、失败和本地兜底信息。
- 使用底部流程按钮统一上一步和下一步操作。

## 10. 智慧模式与本地兜底

项目前端将 AI 能力称为“智慧模式”。后端通过 OpenAI-compatible Chat Completions 接口调用 DeepSeek。

环境变量示例：

```env
DEEPSEEK_API_KEY=your_deepseek_api_key_here
LLM_API_BASE=https://api.deepseek.com
LLM_MODEL=deepseek-chat
LLM_TIMEOUT_SECONDS=90
LLM_RETRY_COUNT=1
```

调用失败时，系统不会直接中断，而是返回本地规则生成的结果，并在 `generation_meta` 中说明是否使用 AI：

```json
{
  "provider": "local",
  "used_llm": false,
  "fallback": true,
  "fallback_reason": "DeepSeek 请求超时",
  "stage": "tree"
}
```

这种设计提高了项目演示稳定性。

## 11. Word 生成设计

Word 生成使用 `python-docx` 处理段落、标题、图片、表格和样式。格式配置以 JSON 形式传递，后端会将其转换为 Word 可识别的格式。

支持的 Word 格式能力包括：

- 正文和标题字体设置
- 中文字号到 pt 的映射
- 标题编号
- 倍数行距和固定磅值行距
- 段前段后，支持磅和行两种单位
- 首行缩进
- 封面、正文标题、目录占位、摘要、参考文献
- 图片插入和图注
- 表格生成

## 20. 不足与改进方向

当前项目仍有一些可以继续优化的方向：

- 文档格式解析仍主要覆盖常见表达，复杂学校模板可能需要继续扩展规则。
- 前端目前主要集中在 `App.vue` 中，后续可以拆分为多个 Vue 组件，提高可维护性。
- 图片插入已经支持基础位置编排，后续可以增加更智能的图片推荐。
- 正文生成质量依赖文本库质量和智慧模式稳定性，后续可以增加更细粒度的章节编辑。
- 数据库目前使用 SQLite，适合本地课程项目，若多人协作部署可迁移到 PostgreSQL。
- 测试主要是编译和构建验证，后续可以增加自动化单元测试和接口测试。

## 21. 总结

TextTreeDoc 是一个面向课程文档生成场景的前后端分离开源项目。项目使用 Vue 3、FastAPI、SQLite 和 python-docx 构建完整流程，实现了文本资料入库、格式配置、结构树生成、图片编排、正文填充和 Word 导出。项目同时支持智慧模式和本地兜底，兼顾生成能力和演示稳定性。

从工程化角度看，项目包含较清晰的代码分层、较完整的开源文档、MIT 许可证、Doxygen 风格注释和可自动生成的 HTML 代码文档，能够满足课程对代码运行、注释规范、文档齐全、许可证合理和仓库提交的要求。
